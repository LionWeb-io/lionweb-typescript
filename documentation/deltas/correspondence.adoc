This document describes the correspondence between commands, events, and deltas as implemented in the LionWeb TypeScript implementation.

Each row states the technical names of a command and the corresponding event, and the section numbers (§) of their descriptions in the link:https://lionweb.io/specification/delta/delta-api.html[Delta API specification].
The last “delta?” column states whether the stated event has a corresponding `IDelta` class in the `@lionweb/class-core` package.

****
* The `ContinuedCommand` and `ContinuedEvent` do not have corresponding delta types, as they are used for message splitting and continuation.
* The `CompositeCommand` and `CompositeEvent` do have corresponding delta types (`CompositeDelta`).
* The `NoOpEvent` has a corresponding `NoOpDelta`, but there is no `NoOpCommand`.
This is a deliberate choice in the Delta API specification, as it’s nonsensical to have the _intention_ to have a `NoOpEvent` produced from a command.
* The `ErrorEvent` does not have a corresponding delta type.
****

=== Delta Naming Convention

If a delta corresponding to an event exists, it has an identifier of the format `<technical name of event>Delta` with the following exceptions:

* For events with names ending in "Event", the "Event" suffix is replaced with "Delta"
* For events with names ending in "Added", the "Added" suffix is replaced with "Delta" (resulting in e.g. PartitionAddedDelta)

This means that all event technical names can be converted to their corresponding delta technical names by replacing "Event" with "Delta" at the end of the event name.

For example:

* `PartitionAddedEvent` &rarr; `PartitionAddedDelta`
* `PropertyChangedEvent` &rarr; `PropertyChangedDelta`
* `ChildMovedFromContainmentInOtherParentEvent` &rarr; `ChildMovedFromContainmentInOtherParentDelta`
